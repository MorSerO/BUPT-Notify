# BUPT-Notify · 北邮校内通知/校内文件 自动转发助手

> 定时自动抓取 → 自动登录统一身份认证 → 抓取「校内通知」和「校内文件」→
> 把最近 10 天内**尚未转发过**的新内容发到你的 QQ 邮箱。
> 顺带把**校园卡余额、未读邮件数**和**未读邮件的标题**一起带上。
> 附一个桌面控制面板，双击图标就能用。

**定时抓取由 Windows 计划任务驱动：每几小时在后台跑一次，跑完就退出——
不需要让软件一直开着，平时也不占内存 / CPU / 显存。**

[![Node](https://img.shields.io/badge/node-%E2%89%A520-339933?logo=node.js&logoColor=white)](https://nodejs.org/)
[![Platform](https://img.shields.io/badge/platform-Windows-0078D4?logo=windows&logoColor=white)](#)
[![License](https://img.shields.io/badge/license-MIT-blue)](LICENSE)
[![Tests](https://img.shields.io/badge/tests-206%20passing-brightgreen)](#测试)

抓取 **my.bupt.edu.cn** 的「校内通知」和「校内文件」，
只看**最近 10 天**、且**此前没转发过**的内容，按你选择的方式投递到本地文件或 QQ 邮箱。

同一份通知里还会带上（每一项都能在面板里单独关掉）：

- **校园卡（北邮通）余额** —— 来自门户首页「待办中心」
- **未读邮件数量** —— 同上
- **未读邮件的标题** —— 来自校园邮箱（Coremail），每条只有标题 + 发件人 + 时间

带一个**桌面控制面板**：设置定时抓取间隔（1–24 小时）、一键开关定时执行、
点「立即抓取」手动触发、
一键开关**定时自动抓取**、保存统一身份认证账号实现**自动登录**。

内容刻意保持简洁：**每条只有标题 + 抓取时间**（以及原文链接），不含正文。

## 一键安装（Windows）

需要 **Windows 10/11** + **Node.js 20+**（[下载](https://nodejs.org/zh-cn/download)，
安装时记得勾选 *Add to PATH*）。

**第一步**：下载本项目

```powershell
git clone https://github.com/MorSerO/BUPT-Notify.git
cd BUPT-Notify
```

> 不用 git 也行：在 GitHub 页面点 **Code → Download ZIP**，解压到任意文件夹
> （路径别带特殊字符即可，整个文件夹之后可以随意移动）。

**第二步**：双击其中一个

| 文件 | 作用 |
|---|---|
| **`install.cmd`** | 安装依赖 + 创建桌面快捷方式 + 立即启动 |
| **`install-with-autostart.cmd`** | 同上，并自动启用**定时自动抓取**（每 3 小时） |

安装脚本会自动：检查 Node 版本 → `npm install` → 生成应用图标 →
创建**桌面和开始菜单快捷方式** → 启动控制面板。

**第三步**：以后直接双击桌面上的 **BUPT-Notify** 图标即可（不弹黑框、
重复双击只会把已有窗口带到前台）。

> **图标点了没反应 / 提示「无法启动脚本文件」？**
> 快捷方式内部保存的是**绝对路径**，所以**移动或重命名项目文件夹之后**它会失效。
> 在项目目录里运行一次 `npm run shortcut` 重建即可（`npm run doctor` 也会检查并提示）。

**第四步**：在控制面板里填三样东西

1. **QQ 邮箱授权码** —— QQ邮箱 → 设置 → 账户 → POP3/IMAP/SMTP服务 → 开启 → 生成授权码
   （是 **16 位授权码**，**不是** QQ 密码），可点「发送测试邮件」当场验证
2. **统一身份认证学号 + 密码** —— 保存后即可自动登录，不再需要手动认证
3. **定时抓取间隔 / 是否启用定时抓取**

装完后想自检，运行 `npm run doctor`。

## 它是怎么工作的

每次运行按下面的顺序执行，任何一步失败都会记录原因并在下一轮重试：

```
   ┌──────────────────────────────────────────────┐
   │ 1. 网络探测                                   │
   │    真正发一次 HTTP 请求访问 my.bupt.edu.cn     │
   └───────────────┬──────────────────────────────┘
                   │ 失败
                   ▼
   ┌──────────────────────────────────────────────┐
   │ 2. 打开 vpn.bupt.edu.cn，请你手动登录 VPN     │
   │    然后每 5 秒重新探测，最多等 15 分钟         │
   └───────────────┬──────────────────────────────┘
                   │ 成功
                   ▼
   ┌──────────────────────────────────────────────┐
   │ 3. 检查统一身份认证（CAS）会话                 │
   │    有效→复用已保存的登录状态                   │
   │    无效→用保存的账号密码自动登录                │
   │    仍失败→提示你打开面板手动登录一次            │
   └───────────────┬──────────────────────────────┘
                   ▼
   ┌──────────────────────────────────────────────┐
   │ 4. 抓取校内通知(1154) / 校内文件(2001)         │
   │    过滤：最近 10 天 且 未转发过                 │
   └───────────────┬──────────────────────────────┘
                   ▼
   ┌──────────────────────────────────────────────┐
   │ 4b. 待办中心：校园卡余额 / 未读邮件数          │
   │     邮箱：未读邮件的标题（同一登录会话）        │
   │     读不到只记一条警告，不影响第 5 步           │
   └───────────────┬──────────────────────────────┘
                   ▼
   ┌──────────────────────────────────────────────┐
   │ 5. 投递：本地 Markdown 文件  和/或  QQ 邮件     │
   │    只有投递成功才记录「已转发」→ 失败会自动重试  │
   └───────────────┬──────────────────────────────┘
                   ▼
         进程退出（Windows 计划任务下次再唤起）
```

## 定时抓取：跑完就退出，不常驻

抓取不是靠一个常驻进程轮询，而是**由 Windows 计划任务每隔几小时唤起一次**：

```
任务计划程序
   │  每 3 小时（01:00 / 04:00 / … / 22:00），以及登录后 60 秒
   ▼
wscript.exe run-hidden.vbs        ← 完全隐藏，不闪控制台
   ▼
node src\main.js --once --quiet   ← 约 3 秒完成抓取与投递
   ▼
进程退出，什么也不留下
```

这样做的直接好处：

| | 效果 |
|---|---|
| **软件关着也能抓** | 定时任务不依赖任何常驻进程，面板关掉、机器重启都不影响 |
| **平时零占用** | 两次执行之间没有任何 node / Chrome 进程，不占内存、CPU、显存 |
| **不打扰使用** | 隐藏窗口执行；**不弹任何对话框**，也不会突然弹出浏览器窗口 |
| **可随时关掉** | 面板里取消勾选「启用定时自动抓取」即可，见下 |

**登录过期怎么办？** 定时运行是后台模式，不会弹浏览器窗口。如果会话失效且
自动登录也失败，它只会写日志并退出（日志在 `logs\`），下一次定时任务会再试。
需要人工登录时，双击桌面图标打开面板登录一次即可 —— 之后会话会被保存复用，
定时任务继续正常工作。

> 想要「一直开着、自己内部轮询」的老模式也可以：把 `config.json` 里
> `poll.mode` 改成 `"resident"`，然后用 `npm start`
> （或面板里勾选常驻模式）。默认是 `"task"`。

## 桌面控制面板

双击桌面快捷方式打开的无边框窗口（Chrome `--app=` 模式）包含：

| 区域 | 功能 |
|---|---|
| **运行控制** | 「立即抓取」/「试运行（不发送）」/**「停止抓取」**/「恢复自动抓取」/「清除登录会话」；实时状态、当前步骤、下次执行时间、上次新增条数 |
| **抓取设置** | 时间窗口天数、获取方式、附带原文链接、**无新内容也发邮件**、**附带校园卡余额/未读邮件数**、**转发未读邮件标题** |
| **定时自动抓取** | 勾选启用 / 取消，**拖动滑轨**选间隔（1–24 小时任意值），一键执行一次（见下文） |
| **登录账号** | 保存统一身份认证账号密码（DPAPI 加密）、清除暂停 |
| **邮箱设置** | 发件 QQ 邮箱、收件邮箱、SMTP 授权码；一键发送测试邮件 |
| **最近转发的内容** | 已转发条目列表，可点进原文 |
| **运行日志** | 实时日志 |

> 面板本身**不常驻轮询**（默认 `poll.mode = "task"`）。它只是控制台：
> 关掉它既不会停止定时抓取，也不会让抓取重复执行。
> 定时执行由计划任务负责，面板每 15 秒刷新一次任务状态与运行记录。

### 定时自动抓取（面板里一键开关）

面板「定时自动抓取」卡片里：

1. 勾选 **「启用定时自动抓取」**
2. **拖动滑轨**选择间隔：**1–24 小时任意值**（想几小时就几小时，不必是能整除 24 的数）
3. 点 **「保存定时设置」**

也可以随时**取消勾选**来关闭它 —— 关闭后不会再有任何自动抓取，
只有你手动点「立即抓取」时才运行。

启用后会注册一个名为 **BUPT-Notify** 的 Windows 计划任务：

- **触发**：**重复间隔**，从你点保存的那一刻起每 N 小时跑一次（N 由滑轨决定，
  例如 3 小时就是 3 小时一次、1.5 小时就是 90 分钟一次），
  另外**登录后 60 秒**也执行一次
- **重复时长**：无限制（永久有效），不是「只重复一天」
- **动作**：隐藏执行 `node src\main.js --once --quiet`，**跑完即退出**
- **常驻进程**：无
- **单次超时**：30 分钟（正常约 3 秒），超时自动结束
- **错过补跑**：勾选 `StartWhenAvailable`，关机错过的会在开机后补上
- 需要管理员权限：**不需要**

命令行等价操作：

```powershell
npm run autostart                  # 按 config.json 的间隔注册
npm run unautostart                # 取消
npm run task-status                # 查看状态（间隔、下次执行、上次结果）

# 指定间隔（0.25–24 小时，可以是小数，例如 1.5）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -IntervalHours 6
```

> **为什么用「重复间隔」而不是「每天的整点」？**
> 面板里的滑轨可以选到 5 小时、7 小时这种**不能整除 24** 的值 ——
> 用「每天铺整点」根本表达不了：5 小时一轮的话，触发点每天都会往后漂，
> 一天顶多也只能铺 4 个。所以这里必须用真正的重复间隔。
>
> 实现上有个坑：模块命令 `New-ScheduledTaskTrigger -RepetitionInterval` 必须同时给
> `-RepetitionDuration`，而 `[TimeSpan]::MaxValue` 会生成 `P99999999DT23H59M59S`，
> 计划任务 XML 判定越界（错误 **0x80041318**）。
> 因此脚本改用 COM（`Schedule.Service`）注册：把 `<Repetition><Interval>` 设为
> `PT3H` 之类，**`<Duration>` 留空即代表永久重复**，这才是真正的无限重复。
> 万一某台机器上 COM 不可用，脚本会自动回退到模块命令 + `P3650D`（十年）。
>
> 顺带一提：重复间隔的起点是注册的时刻，而不是整点。想让它整点跑，
> 就在你想要的整点前后点一次「保存定时设置」。`StartWhenAvailable` 期间错过的会补跑。

### 面板最小化时的资源占用

只有你**主动打开面板**时才会有窗口；定时抓取本身完全无窗口，
所以下面的内容只在你开着面板看的时候才有意义。

- **不常驻浏览器**：登录和抓取都走 HTTP，一轮大约 3 秒，
  结束后**不留下任何 Chrome 进程**（需要浏览器的只有「没有保存账号密码、
  需要你手动登录一次」这一种情况）
- **控制面板走软件渲染**：面板窗口用 `--disable-gpu`、`--disable-gpu-compositing`、
  `--disable-accelerated-2d-canvas`、`--disable-gpu-rasterization` 启动。
  它是个静态页面，不需要硬件加速，因此**不再占用显存**。
  需要说明的是：`--disable-gpu` **不会**让 Chrome 完全不启动 GPU 进程
  （仍会有一个软件渲染的进程），它去掉的是**硬件加速上下文**，也就是显存占用
- **顺带精简进程树**：`--renderer-process-limit=1`、`--disable-extensions`、
  `--disable-sync`、`--disable-component-update`、`--disable-breakpad` 等，
  让面板只保留必要的进程、不做后台同步与更新检查
- **最小化后降低轮询**：窗口最小化时，面板把状态刷新从 **2 秒一次降到 30 秒一次**
  （服务端会返回新的间隔、界面自动采用），不再频繁唤醒 CPU；
  恢复窗口后自动变回 2 秒

> 想让它在后台常驻轮询（老模式）？把 `config.json` 的 `poll.mode` 改成
> `"resident"`，然后用 `npm start`。默认 `"task"` 就是上面这套按需执行。

### 没有新内容时的提醒

勾选「没有新内容也发邮件」后，每次检查如果没有新内容，也会发一封简短邮件
（主题形如 `[北邮通知] 2026-09-25 本次检查没有新内容`），
里面写明检查时间、范围、已检查条数、下次检查时间。

因为默认是每 2 小时检查一次，怕太频繁，所以提供了频率选项：

| 选项 | 说明 |
|---|---|
| **每次检查都发** | 默认。想随时确认程序在跑就选这个 |
| 每 6 / 12 小时最多一次 | 折中 |
| 每天最多一次 | 只在每天第一轮检查后发一封 |

- 只在**邮件模式**（`email` 或 `both`）下有效，纯本地模式不会发
- 发送失败只记日志，**不会**影响本轮结果
- 想彻底关掉，取消勾选即可


### 停止抓取

点 **「停止抓取」** 会立刻彻底停下，做了三件事：

1. **停掉定时轮询** —— 不再安排任何自动抓取；
2. **中断正在进行的任务** —— 取消令牌会打断流水线里的每一个等待点
   （校园网探测、VPN 等待、手动登录等待、翻页、投递前的最后一道检查）；
3. **关闭浏览器** —— 让已经卡住的 Playwright 调用（例如正在进行的
   `page.goto`）立刻失败，这是协作式取消背后的硬停止。

停止状态下面板会显示红色横幅，**「立即抓取」按钮会被禁用**，
直接调用接口也会返回 409。点 **「恢复自动抓取」** 即可恢复（会立刻检查一次）。

为什么不是「设个标志、下一轮生效」？因为一轮抓取可能长时间卡在等待里：

| 卡住的位置 | 最长等待 |
|---|---|
| 等 VPN 连上 | 15 分钟 |
| 等你手动完成 CAS 登录 | 10 分钟 |
| 单次网络探测 | 15 秒 |
| 手动登录轮询 | 每 4 秒一次 |

所以取消必须能打断这些等待本身。实测：在「检查登录状态」阶段点停止，
**312 毫秒**返回、**593 毫秒**内整轮结束。

两个重要保证：

- **停止的一轮绝不投递、也绝不标记「已转发」** —— 投递前有最后一道
  取消检查，所以下次运行会把这些内容当作新内容重新处理，不会漏。
- 被停止的那一轮会记为 `cancelled`，而不是失败，面板上显示「已停止」，
  不会误导你去排查一个并不存在的错误。

> 唯一无法中断的是**已经在发送中的邮件**（SMTP 事务不可回滚）。
> 取消检查发生在发送之前，因此最坏情况是「这一封已经发出去了」。

程序进程本身不会被杀掉，所以面板还可以继续用、随时可以恢复；
要完全退出请用任务管理器结束 `node`。


**技术说明**：面板是一个绑定在 `127.0.0.1` 的本地 HTTP 服务，
页面在打开时会被注入一个随机令牌，所有 `/api` 请求都必须带这个令牌。
这样即使本机有别的程序（或误开的浏览器标签）也无法触发抓取或读取设置。

关闭窗口**不会**停止后台定时任务；要完全退出请用任务管理器结束 `node`，
或卸载自启后重启。

## 校园卡余额和未读邮件

门户首页的「待办中心」里有三行信息，其中两行会跟着每次通知一起发出来：

```
【邮箱】      您有 0 封未读邮件
【北 邮 通】  您当前余额 216.010 元     ← 校园卡
【图书借阅】  共计借阅 0 本
```

通知里长这样（纯文本版）：

```
北邮校内门户新增内容 — 抓取于 2026/09/26 16:03
共 1 条（其中未读邮件 1 封）

校园卡余额 ¥216.01 · 未读邮件 1 封

【未读邮件】（在 https://mail.bupt.edu.cn 登录后可看原文）
1. 关于国庆节期间图书馆开放时间的通知
   图书馆 <library@bupt.edu.cn> | 抓取 2026/09/26 16:03
```

面板顶部也会显示同一组数字（打开邮箱的链接就在旁边）。

### 这些数字是怎么读到的

**余额和未读数**不在首页 HTML 里——首页只给 `【-】` 占位符，真正的数字由一次
AJAX 请求填进去：

```
GET /system/resource/app/cuser/getwxtsA.jsp
→ {"qkje":"0","yjcs":"0","oddfare":"216.010","mail":"0","cgtodo":"0","a":"…"}
     oddfare=校园卡余额  mail=未读邮件数  yjcs=借阅  qkje=欠款
```

这里有两个坑（代码里都处理了）：

- **必须带 `Referer: 首页地址`**，否则接口返回
  `{"result":"false","errorinfo":"错误的访问来源！"}`
- 读不到数字时页面给的是 **`【-】`**，必须当成「未知」而不是数值
  （`Number('')` 是 0、`Number('【-】')` 是 NaN，两种都会在通知里写出假数据）

**未读邮件的标题**要进校园邮箱（Coremail），它的会话是一个跟在 URL 里的 `sid`：

```
1. GET https://register.bupt.cn/mail/login          ← 复用门户的 CAS 登录态
   → 275 字节的脚本：parent.window.location.href = 'http://mail.bupt.edu.cn/cgi-bin/login?...&authkey=…'
2. 跟着那个地址走一次 → 响应里就有 sid，同时把 sid/qm_sid Cookie 存进会话
3. GET /cgi-bin/mail_list?sid=…&folderid=1&flag=new  ← flag=new 才是「只看未读」
```

踩过的坑：

- **`flag=new` 才是未读过滤**。只写 `s=unread` 服务端不认，会把整个收件箱都返回，
  那样连已读邮件都会被转发。
- 邮件列表页是 **gb18030**，而且编码只写在 `<meta>` 里、HTTP 头里没有。
  按 UTF-8 解会把所有标题变成乱码 —— 所以 `httpLogin.decodeBody()` 现在会嗅探字符集。
- 页面里有 `<input name="mailid" type="hidden" value="">` 这种表单辅助元素，
  用 `name="mailid"` 一把抓会把它们当成邮件，多出几条空标题。

> **未读邮件转发一次就够。** 它的去重键是 `mail:<邮件 id>`，规则和通知完全一样：
> 转发成功后记下来，之后即使这封邮件仍是未读状态也不会重复发。
> 去重记录同样受 10 天窗口清理。

想关掉其中任意一项，在面板「抓取设置」里取消勾选
（`portal.status` / `portal.mailbox`，见[配置说明](#配置说明)）。
两项都失败时通知照常发出，只是少了这一段，日志里会有警告。

## 自动登录（不再需要手动认证）

在控制面板「登录账号」里保存学号和密码后，会话过期时程序会**自动登录**，
不再弹窗打扰你。

**登录流程是这样的**（对 `auth.bupt.edu.cn` 逆向确认，含实测数据）：

```
my.bupt.edu.cn  →  302  →  auth.bupt.edu.cn/authserver/login?service=...
                                    │
              用普通 HTTP 提交表单（取 execution → POST 账号密码）
                                    │
                       302 + ticket=ST-xxxx  →  门户会话建立
```

**为什么不用浏览器登录**：站点反爬会拦截自动化 Chrome，但对普通 HTTP 请求放行。
实测（2026-09-25，同一台机器、同一账号）：

| 请求 | 结果 |
|---|---|
| 浏览器 GET `/authserver/cas/login-normal.html` | **400**（Cookie 3 个 / 464 字节） |
| 浏览器 GET `/authserver/css/index.css` | 200（Cookie 2 个 / 127 字节） |
| 浏览器 POST `/authserver/login?service=...` | **400** ← 登录请求本身被拒 |
| 普通 HTTP POST 同一个地址 | **302 + ticket=ST-…** ✓ |

失败的都是携带「页面加载后由 JS 写入的第三个 Cookie」的请求。
排除了 UA、HTTP/2、请求头大小、`Sec-Fetch-*`、Referer、Accept-Encoding——
逐项从普通 HTTP 测试都返回 200。也试过把 HTTP 拿到的 Cookie 注入浏览器，
浏览器仍然未通过校验。

**所以做法是**：用 HTTP 完成登录与抓取，浏览器只在「没有保存凭据、需要你手动登录」
时才打开。好处：

- 登录真的能用（不再是 400）
- 每次轮询不再启动 Chrome（19 个进程 → 0 个），一轮只要约 3 秒
- 会话 Cookie 存到 `data\http-cookies.json`，**重启后直接复用，不会每次都重新登录**

**安全措施**：

1. 密码用 **Windows DPAPI（CryptProtectData）** 加密后存到
   `data\credentials.json`，密文与你的 Windows 账户绑定，
   文件被拷到别的机器也解不开（`npm run doctor` 会显示是否启用了加密）。
2. **失败退避**：连续 3 次被统一身份认证**拒绝登录**后暂停 30 分钟，
   避免把账号弄到锁定。
3. 需要**验证码**时不会硬试，而是提示你手动登录一次。

### 关于「自动登录暂停 30 分钟」

只有**服务器真的拒绝了这次登录**才会计入这个次数。判定依据是 CAS 页面自己
返回的错误信息（页面把提示放在 `#errorDiv`，例如「用户名或密码错误」）——
程序会把这句原文显示给你，而不是自己猜。

以下情况**不会**计入失败次数，也不会触发暂停，因为它们跟密码对不对**毫无关系**：

| 情况 | 说明 |
|---|---|
| 浏览器被关闭 / 你按了「停止抓取」 | 中断导致的操作被取消 |
| 登录页被站点反爬拦截（HTTP 400 空页面） | 请求根本没到达表单 |
| 页面上找不到登录表单 | 页面结构或网络问题 |
| 要求输入验证码 | 需要人工介入，不是密码问题 |
| 抓取被取消（`cancelled`） | 用户主动停止 |

> 这一条是修出来的：早期版本把**任何**失败都计入次数，于是「我自己的停止按钮
> 关掉了浏览器」也会被算成一次登录失败并弹出「连续失败过多，避免账号被锁定」——
> 那是**误导人的提示**。现在计数与暂停状态都由**凭据被拒绝**单独驱动，
> 并且失败的**真实原因**会显示在面板上。

需要提前解除暂停时，两种方法都可以：

- 面板「登录账号」里点 **「清除暂停，立即重试自动登录」**；
- 或命令行 `npm run reset-autologin`；
- 或**重新保存一次账号密码**（保存动作会自动清零，避免改对密码后还被锁着）。

暂停状态和上次失败原因也会写进日志，`npm run doctor` 可查看。

> 注意：如果学校对登录启用了图形验证码，全自动登录就无法完成，
> 此时程序会明确告诉你「需要验证码」，并弹出窗口让你手动登录。
> 当前实测该账号**不需要验证码**（`config.captcha` 为空）。

## 定时任务的命令行用法

面板里的一键开关见上文 [定时自动抓取（面板里一键开关）](#定时自动抓取面板里一键开关)。
下面是等价的命令行用法与细节：

```powershell
npm run autostart      # 按 config.json 的间隔注册定时抓取
npm run unautostart    # 取消定时抓取
npm run task-status    # 查看状态（间隔、触发方式、下次执行、上次结果）
```

安装脚本的参数（不通过 npm 时可直传）：

```powershell
# 指定间隔（1-24 的整数小时）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -IntervalHours 6

# 改登录后的首次延迟 / 不注册「登录后也跑一次」/ 注册后立刻跑一次
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 `
  -DelaySeconds 120 -NoLogonTrigger -RunNow

# 让计划任务改为「登录后打开控制面板」（一般不需要）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -Mode ui
```

查看状态：

```powershell
npm run task-status
Get-ScheduledTaskInfo -TaskName 'BUPT-Notify'      # 上次/下次执行时间与结果码
Start-ScheduledTask  -TaskName 'BUPT-Notify'       # 立即执行一次
Get-ScheduledTask    -TaskName 'BUPT-Notify'       # 查看全部触发器
```

启动器相关：

| 文件 | 作用 |
|---|---|
| `start-bupt-notify.vbs` | 双击启动的入口（隐藏控制台），用相对路径，文件夹可移动 |
| `scripts\create-shortcut.ps1` | 生成 / 修复桌面与开始菜单快捷方式（`npm run shortcut`），并校验指向是否有效 |
| `scripts\make-icon.mjs` | 生成 `assets\bupt-notify.ico` 应用图标 |
| `scripts\check-shortcuts.ps1` | 检查快捷方式指向是否有效（`doctor` 用） |
| `.node-path` | 安装时固化的 node.exe 绝对路径，避免依赖 PATH |
| `scripts\run-hidden.vbs` | 自启时由安装脚本生成的隐藏启动器 |

> 关闭自启**不会**删除正在运行实例的锁文件：脚本会先确认持有锁的进程是否还活着，
> 否则「关掉自启」会让运行中的程序失去单实例保护，之后再次启动会抢端口失败。

### 锁文件（`data\bupt-notify.lock`）

它的作用是**防止两个进程同时抓取**（同时抓会把同一批内容发两遍）。规则是：

| 进程 | 持锁方式 |
|---|---|
| `--once` / `--once --quiet`（计划任务） | 整个进程生命周期 |
| `npm start`（`poll.mode=resident` 常驻轮询） | 整个进程生命周期 |
| 控制面板（`poll.mode=task`，默认） | **只在每次真正抓取的那几秒** |

面板不常驻持锁是有原因的：它平时什么都不做，如果一直占着锁，
计划任务每次都会记录 `已有实例在运行 —— 本轮跳过` 而**什么都不做**，
但任务本身仍然显示成功——这是一个不会报错的静默故障。
（2026-09-26 实测发生过：面板开着的时候 14:15 的那一轮就被这样跳过了。）

所以现在：**面板开着也照常按时抓取**；而如果计划任务恰好在跑，
面板点「立即抓取」会提示「另一个进程正在抓取，请稍后再试」，而不是重复发送。

锁文件里存的是进程号，进程不在了就会被自动接管，所以强制结束进程留下的锁
不会把程序永久卡住。要手动解也可以直接删掉这个文件。

## 关于「登录状态无效」这条提示

如果你看到：

```
[WARN] 登录状态无效: 被重定向到认证地址 (https://auth.bupt.edu.cn/authserver/login?service=...)
```

先别急——**只有它后面接着**「尝试自动登录」**并且失败**时才是问题。正常情况下它只是
「当前还没有会话，准备登录」的意思，下一次运行会变成「复用已保存的登录会话」。

这条提示曾经**每次运行都出现、而且确实是 bug**，原因有两个，都已修复：

**原因一：探测地址选错了。** 程序原来用门户根地址 `http://my.bupt.edu.cn/` 判断是否已登录，
但那其实是一个 **954 字节的 JavaScript 跳转壳**：

```html
<script>window.location.href="xs_index.jsp?urltype=tree.TreeTempUrl&wbtreeid=1541"</script>
```

里面既没有 `clogout.jsp` 也没有「欢迎您」。真实浏览器会执行这段 JS 跳过去，所以偶尔能骗过去；
但只看页面内容时会得出「未登录」的结论——**即使会话完全正常**。

现在改为探测**真正需要登录的页面**（两个栏目的 `list.jsp`）：能读到就说明已登录，
而且顺带确认了抓取目标可访问。

**原因二：浏览器登录本身走不通**（HTTP 400，见上文）。所以每次都在这里失败、每次都要重来。

### 会话会保留下来

登录成功后，Cookie 会存到 `data\http-cookies.json`，**重启电脑后仍然有效**，
不需要每次重新登录（CAS 的 `CASTGC` 票据有效期通常为数天到数周）。
只有在真正过期时才会重新登录。

想手动清除时，面板上点「清除登录会话」即可。

## 配置说明

`config.json` 由向导生成，也可手动编辑。**所有字段都有默认值**
（见 `config.example.json`），只需要写你要改的部分。

```jsonc
{
  // 抓哪些栏目（treeId 来自门户自己链接里的 wbtreeid）
  "targets": [
    { "key": "notice",   "name": "校内通知", "treeId": "1154",
      "path": "list.jsp?urltype=tree.TreeTempUrl&wbtreeid=1154" },
    { "key": "document", "name": "校内文件", "treeId": "2001",
      "path": "list.jsp?urltype=tree.TreeTempUrl&wbtreeid=2001" }
  ],

  "windowDays": 10,        // 只看最近 N 天（面板里的「只看最近多少天内的内容」）
  "maxPages": 3,           // 每个栏目至少翻几页；窗口很宽时会自动增加（上限 12 页）

  "output": {
    "mode": "local",           // local | email | both
    "localDir": "output",      // 本地 Markdown 输出目录
    "includeLink": true,       // 是否附原文链接
    "includePublishDate": false, // 是否附发布日期（默认关闭，保持简洁）
    "includeSource": true      // 是否标注 [校内通知]/[校内文件]
  },

  "email": {
    "host": "smtp.qq.com", "port": 465, "secure": true,
    "user": "你的QQ号@qq.com",     // 发件邮箱
    "pass": "16位授权码",          // 或者写 "${QQ_SMTP_PASS}" 用环境变量
    "to": ["收件邮箱@example.com"],
    "subjectPrefix": "[北邮通知]"
  },

  "poll": { "intervalMinutes": 120, "jitterSeconds": 90 },

  // 校园卡余额 / 未读邮件数 / 未读邮件标题（面板里可单独开关）
  "portal": {
    "status": true,        // 附带校园卡余额和未读邮件数量
    "mailbox": true,       // 转发未读邮件的标题
    "mailBase": "https://mail.bupt.edu.cn",  // 校园邮箱地址
    "mailFolderId": 1,     // 收件箱
    "maxMails": 20         // 一次最多转发多少条未读邮件标题
  },

  "network": {
    "vpnPortalUrl": "https://vpn.bupt.edu.cn/",
    "waitTimeoutMs": 900000,   // 等 VPN 登录最多 15 分钟
    "pollIntervalMs": 5000
  },

  "session": {
    "headless": true,          // 日常轮询用无头；需要登录时自动切可见窗口
    "loginTimeoutMs": 600000   // 等 CAS 登录最多 10 分钟
  }
}
```

### 不想把授权码写进文件？

新建一个 `.env`（同样被 git 忽略）：

```ini
QQ_SMTP_PASS=你的16位授权码
```

然后把 `config.json` 里写成 `"pass": "${QQ_SMTP_PASS}"`。

## 工作原理细节

### 1. 为什么用真实 HTTP 请求判断网络，而不是 DNS？

因为电脑上装了**深信服 aTrust**（北邮 VPN 客户端），它会劫持 DNS：
`my.bupt.edu.cn` 会被解析成一个假地址 `198.18.0.3`，
甚至它的 IPv6 记录 `2001:db8:5341:4e47:464f:5200:c612:2` 的十六进制
`53 41 4E 47 46 4F 52` 正好拼出 **"SANGFOR"**。

也就是说：**隧道没连上时，DNS 依然会返回一个地址**，用 DNS 判断网络必然误判。
所以本项目只认真发一次 HTTP 请求的结果，收到任何响应（包括 302 跳登录页）
都算「网络通了」。

### 2. 怎么保证不重复转发？

每条内容的唯一标识直接取自门户 URL：

```
http://my.bupt.edu.cn/content.jsp?urltype=news.NewsContentUrl&wbtreeid=2001&wbnewsid=141749
                                                                  ^^^^^^^^^^^^^  ^^^^^^^^^^^^^^
                                                                  栏目           内容 ID
```

用 `栏目:内容ID`（如 `2001:141749`）作为去重键。它比「标题哈希」可靠得多：
标题被修改、列表重新排序、条目在多个标签页里重复出现，都不会导致重复转发
或漏转发。

> 注意：门户首页会把同一条内容渲染 2~3 次（一个隐藏的 `<a>` 加一张头条卡片），
> 解析器会按 ID 合并成一条。

### 3. 什么时候才算「已转发」？

**只有投递成功之后**才写入 `forwardedAt`。如果邮件发失败（比如网络抖动、
授权码被重置），这条内容**不会被标记**，下一轮会自动重试。

文件、状态写入都用「先写临时文件再改名」的原子方式，断电不会写坏状态。

### 4. 「只看最近多少天」是怎么算的？

- **有日期**的内容：发布日期在 `今天 - N 天` 到 `今天` 之间（含两端）。
- **没有日期**的内容：无法判断新旧，于是**只依赖「是否已转发」** ——
  转发一次后永不再发。这样可以保证投递失败时仍会重试，不会丢。
- 状态清理：当一条记录的**发布日期**和**记录时间**都超出窗口后才会删除。

#### 窗口和翻页的关系（这里修过一个 bug）

每个列表页只有 **20 条**，所以「只看最近 90 天、但只读第 1 页」这种组合
拿到的东西是残缺的 —— 窗口设置看起来就"没生效"。

而且以前**翻页根本没生效过**：

- 真实的分页链接长这样：`?totalpage=18&PAGENUM=2&urltype=tree.TreeTempUrl&wbtreeid=2001`
  （`totalpage` 是**总页数**，紧挨在页码前面）。旧的正则没加边界，
  先匹配到了 `totalpage=18` 里的 `page=18`，于是每个分页链接都被当成"第 18 页"
  （校内通知那个栏目是"第 1602 页"），`第 2 页` 永远找不到 → **永远只读第 1 页**。
- 分页链接是纯查询串（`?totalpage=…&PAGENUM=2`），之前是按门户**根地址**解析的，
  于是变成 `http://my.bupt.edu.cn/?…` —— 那是一个 954 字节的 JS 跳转壳，0 条内容。

现在两者都修好了，并且每个栏目实际会翻几页由窗口决定：

| 窗口 | 每个栏目最多翻 | 说明 |
|---|---|---|
| ≤ 90 天 | `maxPages`（默认 3） | 一页 20 条，通常第 1 页就够了 |
| 200 天 | 7 页 | 大约一个月一页 |
| 365 天 | 12 页 | 硬上限，避免一次抓几百页 |

翻页在**某一页最旧的条目已经早于窗口起点**时立刻停止，所以窗口越小抓得越快。
实测（2026-09-26，对着真实门户）：

| 窗口 | 实际抓取 | 命中窗口 | 最旧条目 |
|---|---|---|---|
| 10 天 | 40 条（1+1 页） | 19 条 | 2026-09-23 |
| 90 天 | 40 条（1+1 页） | 24 条 | 2026-07-03 |
| 200 天 | 200 条（7+3 页） | 183 条 | 2026-03-10 |
| 365 天 | 301 条（12+4 页） | 295 条 | 2025-11-06 |

> 面板上那个输入框下面会直接写出「每个栏目最多翻 N 页」，改数字时会预览新值，
> 所以这个设置不再是黑盒。
>
> 另外提醒：**把窗口调大会一次性带上更多旧内容**（因为它们在更长的窗口里
> 从未被转发过），这是符合预期的。

### 5. 登录状态会过期吗？

会。CAS Cookie 通常有几天到几周的有效期。本项目用
**独立的 Chrome 配置目录**（`data\chrome-profile`）保存登录状态：

- 有效 → 无头模式静默复用，你完全无感。
- 失效 → 用保存的账号密码**自动登录**（见上文）。
- 自动登录也失败 → 自动切换到**可见窗口**让你登录一次，
  成功后自动保存 Cookie 并继续。

这个目录和你的日常 Chrome 配置**完全隔离**，所以不需要关掉 Chrome，
也不会影响你自己的登录状态。

### 6. 踩过的两个坑（都已在代码里处理）

这两个问题是实测发现的，注释里也写了原因，方便以后排查：

**坑一：CAS 对「带着旧匿名 Cookie」的请求返回 400 空页面。**

登录页第一次访问正常（HTTP 200），之后再访问就变成
**HTTP 400 + 39 字节空 body**。用对照实验确认了原因：

| 条件 | 连续三次访问结果 |
|---|---|
| 伪造 User-Agent | 200 → 400 → 400 |
| 真实 User-Agent | 200 → 400 → 400 |
| **清除 Cookie 后** | **200 → 200 → 200** ✓ |

所以**不是** UA 问题（一开始怀疑是 `Sec-CH-UA` 与 UA 不一致触发了 WAF，
实验证明无关），而是**过期的匿名 CAS Cookie**。

后果本来很严重：登录页会**一片空白**，自动登录和手动登录都会失败。
现在 `PortalSession.clearAuthCookies()` 会在发现表单不可用时清掉这些 Cookie 重试。

**坑二：真正可见的登录表单在一个全屏 iframe 里，而 iframe 会被反爬拦截。**

CAS 页面的结构是：

```html
<iframe id="loginIframe" src="/authserver/cas/login-normal.html">  ← 完整登录界面（100vw×100vh）
<div id="default" style="display:none">                            ← 兼容性视图回退表单
  <form id="loginForm"> … username / password / submit … </form>
</div>
```

自动化浏览器访问 `login-normal.html` 会被站点的反爬机制拦下：**HTTP 400 + 6 字节空 body**。
实测各请求的对比（同一浏览器、同一条连接）：

| 状态 | Cookie 数 | Cookie 字节 | 请求 |
|---|---|---|---|
| 200 | 0 | 0 | 主登录页 |
| 200 | 2 | 127 | js / css / init.js |
| **400** | **3** | **464** | **login-normal.html** |

失败请求上多出**第三个、体积很大的 Cookie**（页面加载后由 JS 写入）。
排除了以下原因（都做过对照实验）：伪造 User-Agent、HTTP/2、请求头大小、
`Sec-Fetch-*`、Referer、Accept-Encoding —— 逐项测试均返回 200，唯独真实浏览器带该
Cookie 时 400。这是**服务端反爬行为**，对有头/无头浏览器一视同仁，本项目不去绕过它。

**真正的问题在于它的副作用**：这个 iframe 是**全屏且占位的**——
坏掉之后它既**盖住**了回退表单，又因为仍在正常文档流里把回退表单**推到 y≈1285**
（视口只有 900 高）。结果就是窗口**一片空白**，用户连输密码的地方都找不到。

**修复**：`PortalSession.prepareManualLoginUi()` 会检测 iframe 是否真的渲染出了登录表单；
如果没渲染出来，就把 iframe 从布局中**彻底移除**（`display:none`），
并把内置回退表单显示在页面顶部：

```
修复前: 用户名输入框 y=1285（在视口外，且被 iframe 盖住）→ 一片空白
修复后: 用户名输入框 y=157（首屏可见，elementFromPoint 命中的就是输入框本身）
```

这份回退表单是 CAS 自己的「兼容性视图」，是标准表单 POST，带一次性 `execution`
字段，**可以正常登录**。修好后这些都有回归测试保护：

```powershell
node tools\test-manual-login-ui.mjs   # 本地 fixture，复现空白 → 验证修复
node tools\test-manual-login.mjs      # 对真实 CAS 页面验证
```

这些行为都有回归测试保护（`test/cas-form.test.mjs` 以及上面两个脚本），
如果学校改版，测试会先失败而不是让程序悄悄登不上。

## 常见问题排查

### 每次都提示要登录 VPN

- 确认 aTrust 客户端已登录并且隧道已建立。
- 手动浏览器打开 `http://my.bupt.edu.cn/` 看是否能访问。
- 先跑 `npm run check`，它会明确告诉你网络/登录哪一步没过。

### 邮件发不出去，报 `535 Login fail`

`email.pass` 填错了。必须是 **16 位授权码**，不是 QQ 密码：

1. QQ邮箱网页版 → 设置 → 账户
2. 找到 **POP3/IMAP/SMTP服务**，点 **开启**（需要短信验证）
3. 生成授权码，复制那 16 位字母
4. `npm run setup` 重填，或改 `config.json`

### `doctor` 报「无法启动浏览器」

需要**已安装 Google Chrome**。项目复用系统 Chrome，不下载 Chromium。
装好后重跑 `npm run doctor`。

### 抓取到 0 条，日志说「模板可能已变更」

门户改版了，或者 `treeId` 变了。处理方法：

1. 在浏览器打开对应栏目，地址栏里的 `wbtreeid=xxxx` 就是新 ID。
2. 更新 `config.json` 的 `targets[].treeId` 和 `path`。
3. 用 `npm run parse -- 保存的页面.html` 离线验证解析结果。

### 想重新开始（清空「已转发」记录）

删掉 `data\state.json` 即可。下次运行会把窗口内的所有内容当成新的转发一遍。

### 觉得本地文件/邮件太多

把 `windowDays` 调小，或者把 `poll.intervalMinutes` 调大。

## 测试

```powershell
npm run verify     # 206 个单元测试 + 端到端离线冒烟测试
```

全部离线运行，不访问网络、不启动浏览器：

- **解析器**：真实 VSB 模板（头条卡片 / 普通条目 / 中文月日 / 无日期）、
  同一条目重复渲染去重、栏目过滤、翻页链接发现
- **页面判定**：真实抓取的 clogin 错误页、CAS 登录页、认证跳转 URL ——
  确保「未登录」不会被误报成「模板已变更」
- **CAS 登录契约**：`doLogin` 签名、`firstLogin` 一次性闩锁、隐藏 `#default` 面板、
  验证码条件判断 —— 学校改版时测试会先失败
- **状态**：只在转发成功后标记、幂等、10 天窗口清理、损坏文件降级、重启后仍去重
- **窗口过滤**：边界（今天 / 恰好 10 天前 / 11 天前）、失败后重试、超窗后不重复
- **翻页**：真实分页参数（`totalpage` 与 `PAGENUM` 相邻，`page` 不能匹配进
  `totalpage`）、纯查询串要按**列表页**而不是门户根地址解析、
  窗口越大翻得越多、某一页超出窗口就停、任何窗口下都不放出越界条目
- **输出**：简洁格式（标题 + 抓取时间）、不含正文、每日文件追加、邮件主题计数
- **停止抓取**：取消令牌语义、定时器中途唤醒、网络探测即时中断、
  翻页中途退出、停止的一轮不标记任何内容、调度停止与恢复、
  被停止的轮次记为 `cancelled` 而非失败
- **控制面板 API**：令牌鉴权、间隔边界（60–1440 分钟）、凭据加解密、
  凭据不泄露、并发保护、停止/恢复、路径穿越防护、畸形 JSON 不崩溃
- **待办中心组件**：`【-】` 被当作「未知」而不是 0、接口拒绝
  （`错误的访问来源`）不会伪造数据、字段缺失、非 JSON 响应
- **未读邮件**：隐藏表单元素不被当成邮件、真实主题/发件人/时间提取、
  已读邮件在未过滤时被排除、`flag=new` 时信任服务端、
  gb18030 字节能被正确解码（含「声明 UTF-8 其实是 GBK」的兜底）

### 需要联网的验证（可选）

单元测试全离线，另外有一个真机脚本（命令见[命令行](#命令行)的
「需要联网的验证脚本」）可以对照真实门户跑一遍。

它会走 `collector.collectExtras()`（也就是应用真正走的代码路径），
校验余额是个合理数字、标题没有乱码、面板显示的数量与列表一致，
并打印出通知正文的样子。`--self-mail` 会在你的校园邮箱里留一封
`[BUPT-Notify 自测]` 开头的邮件，看完删掉即可。
